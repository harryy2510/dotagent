# TanStack Start on Cloudflare Workers

## Routing

- File-based routes (TanStack Router). The route tree (`routeTree.gen.ts`) is generated by the
  dev server and build; never edit or generate it by hand.
- Router context: `{ queryClient, session }` (whatever the root `beforeLoad` primes).
- `getRouter()` creates a new router and QueryClient **per request** on the server; never a
  module-level singleton (state would leak between users).
- Links are typed: `<Link to="/projects/$projectId" params={{ projectId }} search={{ tab: 'keys' }} />`;
  never string-built URLs.
- Search params are validated with a Zod schema in `validateSearch` and are the home for
  shareable UI state (tabs, filters, pagination).

## Layouts and guards

- Pathless layout routes group pages: `_auth` (guest only: redirect signed-in users away) and
  `_authed` (signed in: redirect guests to sign-in with `?redirect=`).
- Guards run in `beforeLoad`. **Guards are UX, not security:** every server function and API
  route still checks authorization itself.
- Layout routes own the chrome (sidebar, top bar) and the `errorComponent` for their subtree.

## Data loading

- Loaders prime the cache: `await context.queryClient.ensureQueryData(projectQuery(projectId))`.
- Components read with `useSuspenseQuery(projectQuery(projectId))` (see `react-query-mutative`);
  never `useLoaderData` for query data.
- One request per page load where possible: a bootstrap query for the signed-in shell instead of
  several waterfalls.

## Server functions

```ts
// src/api/projects/requests.ts  (never in a .tsx file)
import { createServerFn } from '@tanstack/react-start'
import { renameProjectInput } from './schemas'

export const renameProject = createServerFn({ method: 'POST' })
	.inputValidator(renameProjectInput)
	.handler(async ({ data }) => {
		const session = await requireSession()
		await requireRole(session, data.projectId, ['owner', 'admin'])
		return projects.rename(session, data)
	})
```

- Every server function is a public HTTP endpoint: validate input with `.inputValidator(schema)`
  (never the old `.validator()`), authenticate, authorize the exact resource and tenant, then act.
- Server-only code (database clients, secrets, admin SDKs) lives in modules imported only by
  server functions; never import them from components, and never hide a server import behind a
  dynamic `import()`: fix the import graph.
- Errors: throw the app's typed error (code + safe message); the global mutation handler shows
  the message. Never return stack traces or provider payloads.
- Bindings and secrets come from the Worker environment (`cloudflare:workers` `env` or the request
  context), typed by generated Worker types; never `process.env`.

## Fast Refresh boundaries

TSX files that export components or hooks must not export anything else. In route files, the
only extra export allowed is `Route`. Move these out of `.tsx` into colocated `.ts` modules named
by responsibility:

| Kind                                   | Module             |
| -------------------------------------- | ------------------ |
| `validateSearch` schemas               | `*-search.ts`      |
| Loaders, `beforeLoad`, route data      | `*-loader.ts`, `route-data.ts` |
| Head and metadata builders             | `*-meta.ts`        |
| Variants and class helpers             | `*.variants.ts`    |
| Labels, path builders, constants       | `*-labels.ts`      |
| Server functions                       | `api/<domain>/requests.ts` |

Avoid vague names (`utils`, `helpers`, `copy`) unless the repo already uses them. If the repo has
a Fast Refresh guard script, run it with the other checks; never suppress it.

## Breadcrumbs

Routes declare a static label in `staticData.breadcrumb` or a dynamic one returned from
`beforeLoad` as `context.breadcrumb`; one hook reads `useMatches()` and the top bar renders them.
No effects, no global state.

## Head and metadata

The root route sets charset, viewport, default title and description, theme colour, icons and
manifest; routes override `head` through a `*-meta.ts` builder. Static assets in `public/`.

## Errors and not found

- `errorComponent` on layout routes; `notFoundComponent` on the root; per-route overrides where
  the recovery differs.
- Error screens say what happened and how to recover, in the product's words.

## Build config

Vite+ owns the config (`vite` and `toolchain` skills):

```ts
// vite.config.ts
import { cloudflare } from '@cloudflare/vite-plugin'
import tailwindcss from '@tailwindcss/vite'
import { tanstackStart } from '@tanstack/react-start/plugin/vite'
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite-plus'

export default defineConfig({
	plugins: [cloudflare({ viteEnvironment: { name: 'ssr' } }), tailwindcss(), tanstackStart(), react()]
	// fmt, lint, test, staged: see the toolchain skill
})
```

Never `app.config.ts` or vinxi (the pre-1.0 Start setup).

## Deployment

Cloudflare Workers with static assets (not Pages for new apps), configured in `wrangler.jsonc`
(`cloudflare` skill). Deploys run in CI or by the user; agents never deploy or run `wrangler`
commands against an account.
